## 한눈에 요약

AI 코딩 에이전트가 빠르게 발전하면서, 숙련된 개발자들 사이에서도 "요즘은 직접 코드를 거의 안 쓴다"는 이야기가 심심치 않게 들립니다. 그렇다면 소프트웨어 엔지니어링은 사라지는 걸까요?

원문의 핵심 주장은 이렇습니다.

> **코딩이 사라지는 것이 아니라, 코드 작성이 개발의 핵심 병목에서 빠지고 있다.**

즉 **코드 작성의 가치는 낮아지지만, 소프트웨어 엔지니어링의 가치는 오히려 더 높아진다**는 것입니다. 하나씩 살펴보겠습니다.

## 코드 작성보다 중요해지는 역량들

AI가 구현(implementation)을 담당하게 되면, 엔지니어에게 남는 일은 그 앞뒤 단계입니다. 구체적으로는 다음 역량들이 전면에 나옵니다.

- **문제 분해**: 큰 요구사항을 AI가 처리할 수 있는 작은 작업 단위로 쪼개는 능력
- **요구사항 정의**: 기능 요구사항은 물론, 성능·보안·확장성 같은 비기능 요구사항까지 명확히 적어내는 능력
- **아키텍처 설계**: 시스템 경계를 어디에 그을지 결정하는 능력
- **검증 인프라 구축**: 테스트, CI/CD, Observability를 갖추는 능력
- **결과 검증**: AI가 만들어낸 산출물이 정말 맞는지 판단하는 능력
- **프로덕션 책임**: 실제 운영에서 터지는 문제를 끝까지 책임지는 능력

흥미로운 지점은, 이 목록이 과거에는 **주로 시니어 엔지니어에게 요구되던 역량**이라는 점입니다. 앞으로는 이것들이 '시니어의 덕목'이 아니라 '일반적인 개발 역량'의 기준선이 될 수 있습니다.

## 테스트와 피드백 루프의 중요성은 더 커진다

AI가 많은 코드를 '안전하게' 쓰려면, 자기가 뭘 잘못했는지 알려주는 장치가 반드시 필요합니다. 결국 다음과 같은 자동화된 피드백 루프가 전제 조건이 됩니다.

```
코드 생성 → 빌드/린트 → 테스트 → 실패 피드백 → 수정
```

그래서 "AI가 코드를 써주니 테스트는 덜 중요해지겠네"는 정확히 거꾸로 된 결론입니다. **테스트는 AI 에이전트가 딛고 서는 발판**이기 때문에, 오히려 그 중요성이 커집니다. 테스트가 부실한 코드베이스는 AI에게도 위험한 작업장입니다.

## 코드가 싸지면, 코드가 너무 많아진다

AI로 코드 **생산** 비용은 극적으로 낮아집니다. 하지만 **유지보수** 비용까지 같이 낮아지는 것은 아닙니다. 코드가 빠르게 늘어나면 함께 늘어나는 것들이 있습니다.

- 버그
- 보안 취약점
- 기술 부채
- 복잡성
- 인프라 비용

그래서 조직이 던져야 할 질문이 바뀝니다. "AI가 코드를 얼마나 많이 만들어낼 수 있는가?"가 아니라,

> **우리 조직은 더 많은 코드를 안전하게 받아들일 수 있는가?**

생산 속도가 아니라 **흡수 능력(absorption capacity)**이 병목이 되는 셈입니다.

## 주니어 개발자의 성장 경로도 바뀐다

지금까지의 성장 방식은 비교적 명확했습니다. 코드를 많이 쓰다 보면 설계 감각이 생기고, 장애를 겪으면서 테스트의 필요성을 체감하고, 그 과정에서 아키텍처를 배웠습니다. **손으로 쓰는 양이 경험으로 환산되는** 구조였죠.

그런데 AI가 구현을 대신하면, 주니어는 그 축적 과정을 건너뛴 채 처음부터 문제 분해와 검증 능력을 요구받게 됩니다. 난이도가 오히려 올라가는 셈입니다.

그래서 원문은 다소 역설적인 결론을 내립니다. **컴퓨터 과학과 소프트웨어 엔지니어링 기본기의 중요성이 더 커진다**는 것입니다. AI가 만든 코드를 판단하려면, 판단 기준이 머릿속에 있어야 하니까요.

## 정리하며

AI가 대부분의 코드를 작성하게 되더라도 소프트웨어 엔지니어는 사라지지 않습니다. 다만 역할의 무게중심이 이동합니다.

| 기존 | 앞으로 |
| --- | --- |
| 코드를 작성하는 사람 | 문제를 정의하는 사람 |
| | 시스템을 설계하는 사람 |
| | AI의 산출물을 검증하는 사람 |
| | 프로덕션에 책임지는 사람 |

결국 이런 이야기입니다. 타이핑은 값싸졌지만, **무엇을 왜 만들어야 하는지 판단하는 일**은 여전히 비싸고 앞으로 더 비싸질 겁니다. AI 시대에 살아남는 개발자는 코드를 빨리 쓰는 사람이 아니라, 쏟아지는 코드를 감당할 수 있는 시스템을 만들어두는 사람일지도 모릅니다.
