## 한눈에 보는 요약

- **Hermeum**은 팀에 맞는 **Hermes agent**를 자동으로 구성하고 배포해 주는 오픈소스 플랫폼입니다.
- 소울(soul), 스킬, MCP, 플러그인, 크론까지 **LLM이 알아서 설정**해 주기 때문에 개발자가 아니어도 에이전트를 만들 수 있습니다.
- 모든 설정이 **하나의 YAML 파일**로 관리되어 템플릿화와 공유가 쉽습니다.
- GeekNews의 Show GN으로 공개되었으며, 제작자가 직접 피드백을 받고 있습니다.

## 왜 만들어졌을까: '에이전트 사일로' 문제

요즘 사내에서 AI 에이전트를 도입하는 팀이 빠르게 늘고 있습니다. 문제는 그 다음입니다. 개발팀은 개발팀대로, 마케팅팀은 마케팅팀대로 각자 에이전트를 만들고 각자 슬랙에 연동합니다.

결과적으로 이런 상황이 벌어집니다.

- 비슷한 에이전트가 팀 수만큼 중복으로 만들어짐
- 설정 방식이 제각각이라 노하우가 팀 밖으로 공유되지 않음
- 에이전트를 만들 줄 아는 개발자가 있는 팀만 혜택을 봄

제작자는 회사에서 이 **사일로(silo)** 가 늘어나는 것을 직접 목격했고, 그 문제를 풀기 위해 Hermeum을 시작했다고 밝혔습니다. 즉 "에이전트를 더 잘 만드는 법"이 아니라 "조직 전체가 같은 방식으로 에이전트를 만들게 하는 법"에 초점이 맞춰진 프로젝트입니다.

## Hermeum이 자동으로 잡아주는 것들

Hermeum은 Hermes agent를 띄울 때 필요한 구성 요소를 한 번에 세팅해 줍니다.

| 구성 요소 | 역할 |
| --- | --- |
| **소울(soul)** | 에이전트의 성격과 역할, 말투 등 정체성 정의 |
| **스킬(skill)** | 에이전트가 수행할 수 있는 구체적인 작업 능력 |
| **MCP** | 외부 데이터·도구와 연결하는 표준 인터페이스 |
| **플러그인** | 기능 확장을 위한 추가 모듈 |
| **크론(cron)** | 정해진 주기로 자동 실행되는 스케줄 작업 |

보통 이 다섯 가지를 손으로 맞추려면 문서를 뒤져가며 상당한 시간을 써야 합니다. Hermeum은 이 과정을 "딸깍" 수준으로 줄이는 것을 목표로 합니다.

## 가장 큰 차별점 두 가지

### 1. LLM 기반 자동 설정 — 비개발자도 사용 가능

Hermeum의 핵심은 **설정 자체를 LLM이 대신해 준다**는 점입니다. 사용자가 원하는 에이전트의 목적을 설명하면, 그에 맞는 스킬과 연동, 스케줄 구성을 알아서 채워 넣습니다.

이 덕분에 YAML 문법이나 MCP 스펙을 모르는 기획자, 마케터, 운영 담당자도 자기 팀에 필요한 에이전트를 직접 만들어 쓸 수 있습니다. "AI 도입은 개발팀에 요청해야 하는 일"이라는 병목을 없애는 접근입니다.

### 2. 설정은 단 하나의 YAML — 템플릿화와 공유가 쉬움

에이전트의 모든 구성이 **단일 YAML 파일**로 표현됩니다. 이 구조가 주는 이점은 생각보다 큽니다.

- **템플릿화**: 잘 만든 에이전트를 그대로 복제해 다른 팀에 배포
- **공유**: 파일 하나만 주고받으면 설정이 그대로 재현됨
- **버전 관리**: Git에 올려 변경 이력을 추적하고 리뷰 가능
- **표준화**: 조직 전체가 동일한 형식을 쓰게 되어 사일로가 자연스럽게 줄어듦

앞서 이야기한 문제의식과 정확히 맞물리는 설계죠. 각 팀이 따로 헤매는 대신, 검증된 설정 하나를 조직 전체가 재사용하는 구조를 만듭니다.

## 어떤 팀에게 유용할까

다음 상황에 해당한다면 한 번 살펴볼 만합니다.

- 팀마다 슬랙 봇·에이전트를 따로 만들어 관리가 흩어져 있는 조직
- 비개발 직군에서도 AI 에이전트 수요가 있는데 개발 리소스가 부족한 팀
- 반복 업무를 크론 기반으로 자동화하고 싶은 팀
- 에이전트 설정을 코드처럼 버전 관리하고 싶은 팀

## 마치며

Hermeum은 "에이전트를 만드는 것"보다 "에이전트를 조직 차원에서 일관되게 굴리는 것"에 답을 내려는 프로젝트입니다. 오픈소스로 공개되어 있으니, 비슷한 고민을 하고 있다면 직접 써보고 피드백을 남겨 보는 것도 좋겠습니다. 제작자도 사용자 피드백을 적극적으로 기다리고 있다고 하네요.
