## 들어가며

llama.cpp를 비롯한 여러 로컬 LLM 추론 도구의 기반인 텐서 라이브러리 **ggml**이 드디어 **1.0.0** 버전을 내놓았습니다. 1.0이라는 숫자에 걸맞게 이번 릴리스에서는 오래 남아 있던 **폐기 예정(deprecated) API를 걷어냈고**, **FP8 지원**을 넓혔으며, CUDA·Metal·Vulkan·SYCL·OpenCL·WebGPU 등 거의 모든 백엔드의 성능을 손봤습니다.

이 글에서는 변경 사항이 많은 이번 릴리스를 주제별로 나눠 핵심만 정리해 보겠습니다.

## 한눈에 보는 핵심 요약

- **API 정리**: 폐기 예정 공개 API와 기존 `DIAG_MASK_INF` / `DIAG_MASK_ZERO` 연산 제거
- **RPC 프로토콜 v9**: 호환되지 않는 상대의 연결을 거부하고, 로딩 속도와 연결 실패 처리 개선
- **CUDA·Metal**: 행 수가 적은 행렬 곱셈과 MoE 연산 최적화, CUDA에 OCP FP8 지원과 NVFP4 연산 융합 추가
- **FlashAttention·MoE 확장**: Intel용 프리필 커널(Vulkan), 장치 측 MoE 스케줄러(SYCL), Adreno용 분해형 FlashAttention(OpenCL) 추가
- **공통 스케줄러**: 읽지 않는 입력은 업로드하지 않고, MoE 캐시는 캐시 미스 일부를 CPU에서 계산한 뒤 결과를 비동기로 복사

## 1. API와 RPC 호환성 변경: 업그레이드 전에 꼭 확인하세요

메이저 버전답게 **호환성이 깨지는 변경**이 들어 있습니다. ggml을 직접 쓰는 프로젝트라면 이 부분부터 확인하시는 게 좋습니다.

- **폐기 예정 공개 API 제거**: 그동안 deprecated로 표시돼 있던 함수들이 이번에 실제로 삭제됐습니다.
- **`DIAG_MASK_INF` / `DIAG_MASK_ZERO` 연산 제거**: 어텐션 마스킹에 쓰이던 기존 연산이 빠졌습니다.
- **YaRN 설정 확장**: YaRN 보정 경계의 반올림을 제어하는 `ggml_rope_set_truncate` / `ggml_rope_get_truncate`가 추가됐습니다.
- **`TRI` 역전파 구현**: 학습 시나리오에서 쓸 수 있는 연산 범위가 넓어졌습니다.
- **정밀도 처리 정비**: `MUL_MAT`의 src1 정밀도 테스트와 적용 조건을 반영했고, `ggml_prec_set_acc` 호출 시 기준 정밀도를 지키도록 했습니다.

### RPC 프로토콜 v9

여러 머신에 모델을 나눠 돌리는 RPC 백엔드도 바뀌었습니다.

- 프로토콜 버전이 맞지 않는 상대의 연결을 **거부**합니다. 서버와 클라이언트 버전을 함께 올려야 합니다.
- **로딩 시간**이 줄었습니다.
- 접근할 수 없는 엔드포인트나 핸드셰이크 실패가 생겨도 크래시 없이 정상적으로 처리합니다.

> 💡 **에디터 팁**: 분산 추론 환경을 운영 중이라면, 일부 노드만 업데이트하면 연결이 거부될 수 있습니다. 모든 노드를 함께 업그레이드하세요.

## 2. 공통 실행 스케줄러와 MoE 캐시

백엔드와 상관없이 적용되는 공통 계층의 개선 사항입니다.

- **불필요한 업로드 생략**: 스케줄러가 읽지 않는 입력은 업로드하지 않고, 앞선 실행 분할(split)에서 계산된 입력만 프리페치합니다.
- **MoE 캐시의 CPU 협업**: 캐시 미스가 나면 그 일부를 CPU에서 직접 계산하고, 결과를 **비동기로** 복사할 수 있습니다. 전문가(expert) 가중치 일부만 GPU에 올려두는 환경에서 특히 도움이 될 수 있습니다.
- **Meta 백엔드**: 텐서 수가 적은 버퍼의 계산 뷰 한도를 높였습니다.

## 3. CUDA와 Metal: 작은 배치와 MoE에 집중

이번 릴리스에서 가장 눈에 띄는 부분입니다. 로컬 추론에서 흔한 **작은 배치·적은 행 수** 상황을 집중적으로 최적화했습니다.

### CUDA

- **작은 배치용 행렬 곱셈 경로 확장**
  - 배치 크기 **2~24**용 MMQ 추가
  - 행 수가 적은 **BF16** 행렬용 MMVF 추가
- **새 데이터 타입과 연산 융합**
  - **OCP FP8** 지원
  - MMQ에서 **NVFP4** gate/up 행렬 곱셈과 GLU를 하나로 융합
- **FlashAttention 설정 추가**
  - sm70(Volta)에서 헤드 크기 256 지원
  - MMA 경로에 헤드 크기 40/72 추가
- **MoE 개선**
  - 비어 있는 MMQ stream-k 타일 건너뛰기
  - 데이터 배치 선형화
  - 바이어스 적용 후 생기는 NaN 처리
- CUDA 그래프와 메모리 처리도 함께 개선했습니다.

### HIP (AMD)

- 고정 BLAS 작업 공간 사용
- CDNA2용 **MFMA lightning indexer** 추가

### Metal (Apple Silicon)

- **MoE 라우팅 융합**
- 융합 가능한 노드 그룹을 **하나의 명령 버퍼** 안에 유지해 오버헤드를 줄였습니다.

### 공통

- CUDA와 Metal 모두 **radix Top-K**에서 값이 같은 항목이 있어도 선택 결과가 항상 같도록 바꿨습니다. 재현 가능한 결과가 필요한 환경에서 반가운 변화입니다.

## 4. Vulkan, SYCL, OpenCL: 실행 경로 확장

### Vulkan

- **Intel용 FlashAttention 프리필 커널** 추가
- CM2에서 역양자화된 KV 최적화, **RDNA3/4**에서 대형 타일 split-K 활성화
- AMD 독점 드라이버 **26.10.1 이상**에서 대형 coopmat 행렬 곱셈 설정 재활성화
- 텐서 일괄 복사와 **ReBAR 감지** 추가 (ReBAR 미지원 시 BAR 할당 회피)
- MoltenVK의 범위 밖 접근과 FlashAttention 임시 버퍼 크기 검사 버그 수정
- Qualcomm에서 헤드가 큰 경우 스칼라 FlashAttention을 8행으로 제한

### SYCL (Intel)

- **장치 측 MoE 스케줄러** 추가

### OpenCL (Qualcomm Adreno)

- Adreno용 **분해형 FlashAttention** 추가
- 디코딩 성능 개선

---

## 5. WebGPU, Hexagon, CPU 등 그 밖의 백엔드

- **WebGPU**
  - 텐서 일괄 처리 API 지원
  - `get_max_size`가 `maxBufferSize`를 반환
  - `GROUP_NORM`, `MEAN`, `COUNT_EQUAL`, `PAD_REFLECT_1D` 커널 추가
- **Hexagon (Qualcomm NPU)**
  - Q5_0 / Q5_1 양자화 지원
  - `conv_2d` 최적화, `conv_3d` 지원
- **CPU**
  - `MUL_MAT`의 src1을 F32로 전환
  - FlashAttention V를 F32로 누적해 정확도 향상
- **CANN (Huawei Ascend)**: 지원하지 않는 버퍼 유형을 미리 거부
- **ZDNN (IBM Z)**: non-zdnn 텐서 허용, 매 연산 후 계산 텐서 무효화, 릴리스 바이너리의 백엔드 라이브러리 감지 버그 수정

## 마무리: 누구에게 중요한 릴리스일까?

ggml 1.0.0은 **정리와 확장**이 함께 들어간 릴리스입니다.

- **ggml을 직접 쓰는 개발자**라면 폐기 예정 API와 `DIAG_MASK` 계열 연산이 제거됐으니 마이그레이션이 필요합니다.
- **RPC 분산 추론 사용자**는 프로토콜 v9 때문에 모든 노드를 함께 업데이트해야 합니다.
- **일반 llama.cpp 사용자**는 MoE 모델, 작은 배치 추론, FP8·NVFP4 같은 저정밀 포맷에서 성능 향상을 기대할 수 있습니다.

NVIDIA·AMD·Apple·Intel·Qualcomm GPU부터 브라우저(WebGPU)와 NPU(Hexagon)까지 고르게 손본 만큼, 어떤 하드웨어를 쓰든 업데이트해 볼 만한 버전입니다.
